## J. GitHub upload — step by step

### J1. Best repository settings

| Setting | Recommended value |
|---|---|
| **Repository name** | `climate-trend-analyzer` |
| **Description** | `End-to-end climate analytics pipeline: data cleaning, Mann-Kendall trend tests, anomaly detection (Z-score + Isolation Forest), SARIMA forecasting and a Streamlit dashboard for 4 Indian cities (1990–2024).` |
| **Visibility** | Public |
| **Topics / tags** | `climate-data` `data-science` `time-series` `anomaly-detection` `forecasting` `sarima` `mann-kendall` `python` `pandas` `scikit-learn` `statsmodels` `streamlit` `data-visualization` `environmental-data` `climate-change` |
| **Website** (About box) | Your Streamlit Cloud URL once deployed (optional) |

### J2. What must be committed ✅ / never committed ❌

✅ `README.md`, `requirements.txt`, `.gitignore`, `main.py`, `pytest.ini`
✅ `src/`, `app/`, `tests/`, `notebooks/`, `docs/`
✅ `outputs/figures/*.png` (recruiters look at these!), `outputs/tables/*.csv` (small), `reports/*.md`
✅ `data/raw/injected_events.csv` (small ground-truth file)
✅ `images/screenshots/*.png`, `images/demo.gif`

❌ `venv/` (huge, machine-specific) ❌ big CSVs in `data/` (re-generated by `python main.py`) ❌ `.env`, tokens, passwords ❌ `__pycache__/`

The provided `.gitignore` already handles this.

### J3. One-time Git setup

```bash
git --version
git config --global user.name "Your Name"
git config --global user.email "your-github-email@example.com"
git config --global init.defaultBranch main
```

### J4. Create the repository on GitHub (website)

1. Go to **github.com → + (top right) → New repository**.
2. Name: `climate-trend-analyzer`. Description: paste from J1.
3. Public. **Do NOT** tick "Add a README" (you already have one — ticking it causes a push conflict).
4. Click **Create repository** and copy the URL, e.g. `https://github.com/SNischayPrasad/climate-trend-analyzer.git`.

### J5. Connect your local folder and push

Run from inside `Climate-Trend-Analyzer/`:

```bash
git init
git add .
git status
```
Check `git status`: `venv/` and big CSVs must **not** be listed. Then:

```bash
git commit -m "feat: initial project structure and climate data simulator"
git branch -M main
git remote add origin https://github.com/SNischayPrasad/climate-trend-analyzer.git
git push -u origin main
```

The first push opens a browser window to sign in (Git Credential Manager) — log in there. After that, every update is just:

```bash
git add .
git commit -m "your message"
git push
```

### J6. Writing meaningful commit messages

Use the **Conventional Commits** style: `type: short imperative summary` (≤ 72 characters).

| Type | When | Example |
|---|---|---|
| `feat` | new capability | `feat: add Mann-Kendall and Sen's slope trend tests` |
| `fix` | bug fix | `fix: handle leap-day in climatology baseline` |
| `docs` | README / docs only | `docs: add results section and screenshots to README` |
| `refactor` | restructure, no behaviour change | `refactor: move plot styling into utils` |
| `test` | tests | `test: add unit tests for cleaning module` |
| `chore` | config, deps | `chore: pin library versions in requirements.txt` |

❌ Bad: `update`, `final`, `asdf`, `changes`, `final final v2`.

### J7. Uploading screenshots, GIF and video

1. Save screenshots into `images/screenshots/` with the names from section M.
2. Make a GIF of the dashboard (free tools: **ScreenToGif** on Windows, **Kap** on Mac, **Peek** on Linux). Keep it < 10 MB, ~15–25 seconds. Save as `images/demo.gif`.
3. For a longer video (2–3 min walkthrough): upload to YouTube (unlisted) or LinkedIn and link it in the README. Alternatively, edit `README.md` on github.com and drag-drop an `.mp4` (≤ 10 MB) into the editor — GitHub hosts it and inserts a link.
4. Reference images in the README with relative paths:
   ```markdown
   ![Dashboard demo](images/demo.gif)
   ![Temperature trend](outputs/figures/06_temperature_trend.png)
   ```

### J8. Make it recruiter-friendly

- **First screen of README** must answer: what is it, what did you find, what does it look like. (Title → one-line pitch → badges → hero image → key results.)
- Add **badges** (Python version, license) — already in the README.
- Fill the **About** box (description, topics, website).
- **Pin** the repo: GitHub profile → *Customize your pins* → select `climate-trend-analyzer`.
- Add a **LICENSE** (Add file → Create new file → name it `LICENSE` → *Choose a license template* → MIT).
- Create a **Release** `v1.0.0` (Releases → Draft a new release) once finished — it looks professional.
- Optional: deploy the dashboard free on **Streamlit Community Cloud** (share.streamlit.io → New app → pick repo → `app/streamlit_app.py`). Note: the deployed app needs data; either commit the processed CSVs or add a line at the top of the app to run the pipeline when the data is missing.

## L. Commit strategy — 8-day proof-building plan

Work and commit in real stages. Don't fake dates — an honest history across several days, with clear messages, is what impresses reviewers. Each day: commit → push → save proof → write 2–3 lines in a `PROGRESS.md` / personal notes file for LinkedIn.

| Day | What to build & commit | Commit message(s) | Proof to save | Notes for LinkedIn / resume |
|---|---|---|---|---|
| **1** | Folder structure, `requirements.txt`, `.gitignore`, `src/config.py`, `src/utils.py`, skeleton README | `chore: set up project structure and environment` | Screenshot of folder tree in VS Code + `pip list` | "Set up a modular Python project with config-driven design." |
| **2** | `src/data_generator.py`, `src/data_loader.py`, `src/fetch_nasa_power.py` | `feat: add climate data simulator with seasonal cycle, warming trend and extreme events` | `dataset_preview.png` (first rows of raw CSV) | "Simulated 51k+ daily records for 4 cities incl. heatwaves, cold spells, cloudbursts." |
| **3** | `src/preprocessing.py`, `src/feature_engineering.py`, `tests/` (cleaning tests) | `feat: add data cleaning pipeline and quality report` · `feat: engineer climatology, anomaly and IMD season features` | `missing_values.png` + terminal screenshot of quality report | "Cleaned sentinel errors, duplicates, gaps; built 1991–2020 climate normals." |
| **4** | `src/eda.py` + figures 01–05 | `feat: add exploratory analysis and seasonal pattern charts` | `03_seasonal_cycle.png`, `04_correlation_heatmap.png` | "Identified monsoon timing differences between cities." |
| **5** | `src/trend_analysis.py` + figures 06–13 | `feat: add Mann-Kendall, Sen's slope and OLS trend analysis` | `06_temperature_trend.png`, `08_warming_stripes.png` | "Quantified warming of X °C/decade with p < 0.05." |
| **6** | `src/anomaly_detection.py` + figures 14–16 | `feat: add z-score, percentile and Isolation Forest anomaly detection` · `test: evaluate detection against injected ground truth` | `14_temperature_anomalies.png`, evaluation table screenshot | "Detected injected heatwaves with X % recall." |
| **7** | `src/forecasting.py`, `src/report_generator.py`, `main.py`, `app/streamlit_app.py` | `feat: add SARIMA vs linear vs naive forecast back-testing` · `feat: add Streamlit dashboard` | `18_temperature_forecast.png`, dashboard screenshots, **demo GIF** | "Back-tested 3 models; SARIMA RMSE ≈ X °C." |
| **8** | Final README, docs, screenshots, notebook, LICENSE, release v1.0.0 | `docs: complete README with results, architecture and screenshots` | GitHub repo page + README screenshot | Publish LinkedIn post (template in `03_CAREER_KIT.md`). |

**Good habits that signal "real engineer":**
- Small commits, each doing one thing.
- Open a GitHub **Issue** for a future improvement (e.g. "Add NASA POWER real-data comparison") and close it later with a commit: `feat: compare simulated vs NASA POWER data (closes #1)`.
- Run `pytest` before every push.
